# Changelog

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

## [v0.2.3] - 2026-11-10

### Fixed

- Declare the integration as `integration_type: service` instead of `helper`. It creates a
  contract device with many sensors and is not a UI helper, so it was listed under the
  Helpers tab and as "(Helper)" in the add-integration dialog, and was missing from the
  Integrations page. Existing contracts, entity IDs and stored data are unchanged.

## [v0.2.2] - 2026-11-10

### Changed

- Publish a maintenance release of the current HACS-compatible integration.
- Runtime behavior, configuration and entity identifiers are unchanged from v0.2.1.

## [v0.2.1] - 2026-11-10

### Fixed

- Format renamed test imports and patch targets to satisfy CI checks.

## [v0.2.0] - 2026-11-10

### Changed

- Rename the integration's display name to **HA Power Bill AU** in Home Assistant,
  HACS, device metadata and documentation. Rename the domain and integration folder to
  `ha_power_bill_au`, and update imports, tests and repository references.
  Existing installations must remove the old integration and set up the new one.
- Publish releases automatically after tests, HACS and Hassfest validation.

## 0.1.0 - 2026-11-08

### Added

- Initial HA Power Bill AU custom integration with UI tariff configuration, dated plans,
  import costs, export credits, demand charges and tracked device costs.
- HACS metadata, local brand assets and manual installation support.
- GitHub validation for HACS, Hassfest and the existing calculation and integration tests.
- Contributor guidance, issue forms and pull request template.
- A Bronze quality-scale rule assessment, upstream branding/documentation drafts,
  full configuration-flow coverage enforcement, and error-recovery tests.

### Fixed

- Store editable tariff settings in config-entry options and migrate existing contracts
  without changing their IDs or saved usage. Describe every setup and options field.
- Preserve tracked cost entities, customizations and usage when registered source meters
  are renamed. Reject duplicate contracts for renamed meter pairs and keep replacement
  meters from inheriting a previous meter's identity, availability or usage.
- Validate whole-hour demand windows without unhandled NaN/fractional conversions, handle
  empty or invalid recorder responses, and log filtered data and fallback decisions safely.
- Normalize live energy inputs to kWh and reject non-finite or negative readings and tariff
  amounts. Validate cumulative meter selections, calendar months and unique band names.
- Apply stepped feed-in caps consistently to live updates and rebuilt history.
- Derive historical charges from available import statistics instead of household-specific
  dates, avoid duplicate daily/hourly bookings, and retain locally measured usage on reload.
- Preserve unchanged demand peaks when adding future plans, keep band sensors across plan
  changes and distinguish repeated clock times during daylight saving transitions.
- Serialize demand scans with shutdown and delete saved data when a contract is removed.
- Add meter availability, non-identifying diagnostics, regression tests and Ruff CI checks.
- Corrected the minimum Home Assistant version from `2025.6.0` to `2025.8.0`, which provides
  the `OptionsFlowWithReload` API used by the configuration flow.

GitHub release tag: `v0.1.0`. The integration manifest declares `0.1.0`.
