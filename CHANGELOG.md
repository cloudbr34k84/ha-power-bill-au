# Changelog

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

## [v0.5.1] - 2026-11-14

### Changed

- Configure > Distance offers only battery sensors for the car's battery level.

## [v0.5.0] - 2026-11-14

### Added

- **Charging cost per 100 km** (Configure > Distance). Link an electric car's tracked
  charger to the car's odometer for distance, charging cost per 100 km and energy per
  100 km, month to date and in total. With solar pricing the cost is what the charging
  took from the grid.
- With the car's location and battery level, the share of charging done away from home
  is shown as `away_charging_percent`, filled in for the last seven days when linking.
- The window starts where both the odometer and the charger have recorder data, or at
  the moment of linking. Odometer readings that go backwards, or jump further than the
  car could have driven since the last one, are ignored.

## [v0.4.0] - 2026-11-14

### Added

- **Cost per mode** (Configure > Modes). Link a tracked device to a climate, water heater
  or select entity and get cost and energy sensors per mode for today, month to date and
  in total. Mode costs add up to the device's cost, including with solar pricing.
- The last seven days are filled in from the recorder's history when a device is linked.
  After that the integration keeps each hour's mode split permanently, so plan changes
  still reprice past mode costs.
- The last known mode is kept while the mode entity is unavailable, and the link follows
  the mode entity through a rename.

### Changed

- Saved data is written within a minute of a change even while meters report
  continuously. Previously each new reading postponed the write.

## [v0.3.1] - 2026-11-13

### Fixed

- Tracked-device cost sensors are named after the meter's device and its default sensor
  name (for example "Izone Circuit EM Clamp Energy cost today"), so renaming the meter
  entity no longer replaces the device name. A name given to the device is kept. Entity
  IDs are unchanged.
- With solar pricing, untracked usage is also built for days the import meter only has a
  daily total for, so lifetime device plus untracked costs add up to the import cost.

## [v0.3.0] - 2026-11-13

### Added

- **Solar pricing for tracked devices** (Configure > Solar, opt-in per contract). Choose a
  solar production sensor and each tracked device is priced at the grid share of each
  interval: import ÷ (import − export + solar). A car charged from surplus solar costs
  nothing, and devices are no longer priced as if all their energy came from the grid.
- **Untracked usage cost** today, month to date and total when solar pricing is on. Tracked
  devices plus untracked add up to the grid import cost.
- A `pricing` attribute on tracked-device cost sensors: `solar_share` or `import_rate`.

### Changed

- With solar pricing on, device usage is priced per hour (two minutes after the hour ends),
  live and in history alike, instead of on each reading. An import-meter outage is priced
  together with the hour the meter reports again in, and each five-minute slot is priced
  at its own local band, so half-hour time zones are priced correctly. Contracts without a
  solar sensor are unchanged.

## [v0.2.4] - 2026-11-11

### Added

- **Add to the Energy dashboard** in the options menu. After you confirm, it selects the
  lifetime import cost and export credit sensors for the grid meters that match this
  contract. It only fills empty cost fields: a meter with another cost sensor or a price
  set, or one that isn't in the Energy dashboard, is left unchanged.

### Changed

- Make the Energy dashboard sensors obvious: rename the lifetime sensors to
  **Import cost total (Energy dashboard)** and **Export credit total (Energy dashboard)**.
  Entity IDs are unchanged.
- Remove the state class from the cost today and month-to-date sensors. They reset each
  period, so they no longer appear in the Energy dashboard's cost pickers. Home Assistant
  may log a one-time state class change for them.
- Show a notification on first setup naming the two sensors to select in the Energy dashboard.

## [v0.2.3] - 2026-11-10

### Fixed

- Declare the integration as `integration_type: service` instead of `helper`. It creates a
  contract device with many sensors and is not a UI helper, so it was listed under the
  Helpers tab and as "(Helper)" in the add-integration dialog, and was missing from the
  Integrations page. Existing contracts, entity IDs and stored data are unchanged.

## 0.1.0 - 2026-11-08

### Added

- Initial HA Power Bill AU custom integration with UI tariff configuration, dated plans,
  import costs, export credits, demand charges and tracked device costs.
- HACS metadata, local brand assets and manual installation support.
- GitHub validation for HACS, Hassfest and the existing calculation and integration tests.
- Contributor guidance, issue forms and pull request template.
- A Bronze quality-scale rule assessment, upstream branding/documentation drafts,
  full configuration-flow coverage enforcement, and error-recovery tests.

### Fixed

- Store editable tariff settings in config-entry options and migrate existing contracts
  without changing their IDs or saved usage. Describe every setup and options field.
- Preserve tracked cost entities, customizations and usage when registered source meters
  are renamed. Reject duplicate contracts for renamed meter pairs and keep replacement
  meters from inheriting a previous meter's identity, availability or usage.
- Validate whole-hour demand windows without unhandled NaN/fractional conversions, handle
  empty or invalid recorder responses, and log filtered data and fallback decisions safely.
- Normalize live energy inputs to kWh and reject non-finite or negative readings and tariff
  amounts. Validate cumulative meter selections, calendar months and unique band names.
- Apply stepped feed-in caps consistently to live updates and rebuilt history.
- Derive historical charges from available import statistics instead of household-specific
  dates, avoid duplicate daily/hourly bookings, and retain locally measured usage on reload.
- Preserve unchanged demand peaks when adding future plans, keep band sensors across plan
  changes and distinguish repeated clock times during daylight saving transitions.
- Serialize demand scans with shutdown and delete saved data when a contract is removed.
- Add meter availability, non-identifying diagnostics, regression tests and Ruff CI checks.
- Corrected the minimum Home Assistant version from `2025.6.0` to `2025.8.0`, which provides
  the `OptionsFlowWithReload` API used by the configuration flow.

GitHub release tag: `v0.1.0`. The integration manifest declares `0.1.0`.
