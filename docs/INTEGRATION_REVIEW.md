## Architecture

HA Power Bill AU is a calculated helper with sensor entities. A shared, typed runtime coordinates
Home Assistant state events, recorder queries, a minute timer and optional demand scans.
It has no external API, authentication or network polling. Cloud-specific guidance on
HTTP sessions, credential refresh, connection tests and API rate limiting is not applicable.
The existing event-driven runtime provides the shared update layer; a network polling
coordinator is not needed for this integration.

## Standards checked

| Area | Result and evidence |
| --- | --- |
| Time handling | Runtime clocks use `dt_util.now()`. Recorder timestamps are timezone aware; naive recorder datetimes are rejected. Demand grouping preserves distinct daylight-saving folds. |
| Async work | Recorder queries and historical reconstruction run in executors. Storage uses Home Assistant's async `Store`. |
| Runtime ownership | `TariffConfigEntry = ConfigEntry[TariffRuntime]` and `entry.runtime_data` hold per-entry state. |
| Entry lifecycle | Unload awaits the runtime hook, unsubscribes listeners, waits for an in-flight demand scan and flushes storage. Contract removal deletes its stored data. |
| Setup failures | Invalid tariffs raise `ConfigEntryError`; temporary recorder/storage errors raise `ConfigEntryNotReady` for retry. Failed startup does not save an incomplete ledger. |
| Entity metadata | Sensors have stable unique IDs, device information, appropriate units/state classes and frozen keyword-only descriptions. Persistent source identities retain tracked cost entities and ledger keys across registry renames. Band sensors persist across dated plans. |
| Availability | Cost and usage sensors become unavailable when their source meter is invalid; tariff/rate information remains available. |
| Meter validation | Configuration requires distinct cumulative energy meters with supported units and state classes. Live readings normalize Wh/kWh/MWh to kWh and reject negative or non-finite values. |
| Tariff validation | Rates and charges must be finite and nonnegative. Calendar months, demand windows, block sizes and normalized band-name uniqueness are validated. |
| JSON attributes | Entity attributes and saved snapshots contain primitive JSON values. Tests serialize snapshots and diagnostics with `allow_nan=False`. |
| Diagnostics/privacy | Diagnostics expose counts and availability, without provider names, entity IDs, entry IDs, tariff rates or usage amounts. No external credentials are used. |
| History/accounting | Available import history defines fixed-charge start dates. Hourly and daily rows are not booked twice. A bounded one-day buffer preserves uncompiled live increments and deduplicates them once recorder covers them. |
| Feed-in/demand | Live and historical stepped feed-in share the daily cap. Unchanged demand peaks survive future plan additions. Shutdown prevents stale scans from updating the ledger. |
| Code hygiene | Imports are at module scope. Production functions have parameter and return annotations. Ruff lint and formatting checks are included in CI. |
| Packaging | One integration under `custom_components/ha_power_bill_au/`, root HACS metadata/README/license, local brand assets, matching domain, owner and repository URLs. |

The minimum Core version is `2025.8.0`, which provides the `OptionsFlowWithReload` API

## Limits and publication status

- Automated runtime tests use Home Assistant `2026.11.0` on Python 3.14. The minimum version
  is based on API availability; this review does not claim a runtime test of every older
  Core release or an official Integration Quality Scale certification.
- Daily-only history lacks hourly detail and is priced at the plan's noon rate. Residential
  spike limits remain 30 kWh/hour, 300 kWh/day and 4 kWh/five-minute demand slot. Higher
  capacity installations may need different limits.
- Demand estimates depend on retained five-minute recorder data. Actual retailer meter
  sampling and billing rules can differ; entered billed kW takes precedence.
- The pending-increment buffer retains one day of live data. It cannot reconstruct a
  prolonged recorder outage or changes that occurred while the integration was unloaded.
- Historical fixes can change previously overstated lifetime totals. Back up Home Assistant
  before installing this version or changing historical plans.
- The GitHub repository remains private. Public HACS distribution requires a separate
  visibility decision; see the repository's GitHub releases for published versions.
- No live Home Assistant installation was changed or restarted during this review.
