## Timestamps and time

- [x] Runtime clocks use `dt_util.now()`; no calls to `datetime.now()` or `datetime.utcnow()`.
- [x] Runtime imports `from homeassistant.util import dt as dt_util`.

Pure engine functions receive dates/timestamps as arguments rather than reading a clock.
Recorder timestamps are timezone aware; naive datetime inputs are rejected. Daylight-saving
fold handling has a regression test.

## State attributes

- [x] Actual attributes from every sensor in a configured import/export/demand contract
  serialize with `json.dumps(..., allow_nan=False)`.
- [x] Attributes contain no dataclasses, datetime instances or other custom objects.
- [x] No unbounded attribute lists are exposed; current attributes are bounded scalar mappings.
- [x] Demand `peak_at` timestamps are stored as `.isoformat()` strings and exposed as strings.

Evidence: `test_checklist_all_entity_attributes_are_strict_json_with_unique_ids` in
[test_standards.py](../tests/test_standards.py).

## Async patterns

- [x] **N/A — HTTP clients:** the integration makes no HTTP requests.
- [x] No blocking I/O in async handlers. Recorder reads and historical reconstruction use
  executors; persistence uses Home Assistant's async `Store`.
- [x] **N/A — `UpdateFailed`/`ConfigEntryAuthFailed`:** there is no network coordinator or
  authentication. Invalid configuration uses `ConfigEntryError`; transient recorder/storage
  errors and invalid recorder responses use `ConfigEntryNotReady`. Periodic demand failures
  are logged without stopping the timer.

## API and data handling

- [x] Recorder responses are checked before use. A null/invalid top-level response triggers
  setup retry; missing/null per-source rows are handled as empty history. Missing row fields,
  invalid numbers, invalid timestamps and out-of-range changes are filtered explicitly.
- [x] **N/A — GPS/coordinates:** there are no coordinate calculations.
- [x] Filter counts, missing-source rows, saved-data recovery and history fallbacks have
  debug/warning logs. These messages omit entity IDs, provider names and bill values.

Evidence: null/missing-recorder and filtered-statistics tests in
[test_standards.py](../tests/test_standards.py).

## Code structure

- [x] Imports are at module scope, including production modules, tests and developer tools.
- [x] No credentials are used by the integration. Integration-owned log messages do not
  print configuration dictionaries, meter identifiers, tariff rates or usage values.
- [x] Every sensor has a nonempty unique ID; the registered contract's IDs are distinct.
- [x] Typed `entry.runtime_data` holds runtime state; no `hass.data[DOMAIN]` storage is used.
- [x] `TariffSensorDescription` uses `@dataclass(frozen=True, kw_only=True)`.
- [x] **N/A — `DataUpdateCoordinator(config_entry=entry)`:** a shared `TariffRuntime` handles
  Home Assistant events and recorder reads; no DataUpdateCoordinator is instantiated.
- [x] No use of `hass.helpers.*`; helpers are imported directly from their modules.

Evidence: [sensor.py](../custom_components/power_bill/sensor.py),
[runtime.py](../custom_components/power_bill/runtime.py), AST checks and Ruff.

## Config flow

- [x] Form schemas validate user input. Explicit checks cover cumulative meter metadata,
  distinct meter roles, finite/nonnegative amounts, whole-hour windows, supported demand
  blocks, actual calendar months, dates, band coverage and normalized name uniqueness.
- [x] **N/A — connection/authentication tests:** there is no remote service or account.
  Selected meter metadata is validated before creating the entry. Temporarily unavailable
  meters can be configured when their metadata is valid; their usage/cost sensors remain
  unavailable until valid readings arrive.
- [x] Validation failures return translated form errors. Non-finite/fractional demand hours
  are rejected rather than raising an unhandled conversion error. Temporary setup failures
  retry without overwriting the stored ledger.
